## Пайплайн компиляции (content → game)

- Исходники панорамы/частиц/звуков кладём ТОЛЬКО в `content\dota_addons\battlearena\`.
- Компиляция: `game\bin\win64\resourcecompiler.exe -game "…\game\dota" -r -i "<content-путь>"` либо -tools → Asset Browser → Compile.
- Результат с суффиксом `_c` появляется в `game\dota_addons\battlearena\` по тому же пути: `layout/custom_game/*.xml → *.vxml_c`, `scripts/custom_game/*.js → *.vjs_c`, `styles/custom_game/*.css → *.vcss_c`, `images/**/*.png + *_png.vtex → *_png.vtex_c`.
- Новые картинки для HUD: PNG + обёртка `<имя>_png.vtex` (создаётся в Asset Browser).
- Манифест HUD: `content\dota_addons\battlearena\panorama\layout\custom_game\custom_ui_manifest.xml` — новые Hud-элементы добавляются строкой `<CustomUIElement type="Hud" layoutfile="file://{resources}/layout/custom_game/<name>.xml" />`, затем манифест перекомпилировать.
- `game`-папка: Lua (`scripts/vscripts/*.lua`) и KV (`scripts/npc/*.txt`, `scripts/custom_net_tables.txt`, `resource/*.txt`) НЕ компилируются — правятся напрямую в game.
- Panorama XML/CSS/JS всегда класть в `content\...\panorama\`, НЕ в `game\...\panorama\`. В `-tools` режиме Asset Browser и компилятор работают только с `content`.
- После создания/изменения Panorama файлов их нужно скомпилировать (Asset Browser: правый клик → **Compile**), иначе `_c` файлы не создадутся и панель не загрузится.
- Если кастомная панель Panorama не работает — проверь, есть ли `.vxml_c` файл в `game\...\panorama\layout\custom_game\`. Если нет — не скомпилирована.

## Критичные грабли этого движка (проверено эмпирически)

- **`GetSpecialValueFor`/`GetLevelSpecialValueFor` возвращают 0** для кастомных способностей даже при корректном KV (регрессия движка). Читать значения только через `AbilityKV:Get(ability, key)` (`lib/ability_kv.lua`, читает `GetAbilityKeyValues()` напрямую). KV-блок: `AbilityValues` или `AbilitySpecial` (var_type-блоки) — оба парсятся, но читаются только через AbilityKV. **Страховка: duration из KV всегда гардить (`if not d or d <= 0 then d = дефолт end`)** — duration=0 в AddNewModifier = вечный модификатор.
- **`HasBehavior` у способностей не существует** — определять флаги через `GetBehaviorInt()` + `bit.band`.
- **Скриптовые частицы в кастомке без прекэча = "invalid particle definition"** даже для базовых частиц. Каждую частицу, создаваемую через `ParticleManager:CreateParticle` из Lua, обязательно прекэчить в `Precache()` в `addon_game_mode.lua` (`PrecacheResource("particle", path, context)`). Прекэч лечит и «базовые частицы не грузятся».

## Разработка кастомок Dota 2 — что важно знать

- **Архитектура**: `game/` = скомпилированное (что грузит движок), `content/` = исходники (только панорама/частицы/звуки компилируются; Lua и KV правятся прямо в game).
- **KV-формат** (`scripts/npc/*.txt`): корневые ключи `DOTAHeroes` / `DOTAUnits` / `DOTAAbilities`; способности — `BaseClass "ability_datadriven"` (логика в KV-блоках OnSpellStart/Modifiers) или `"ability_lua"` (логика в ScriptFile); спец-значения — `AbilityValues` (для ability_lua) или `AbilitySpecial` (var_type-блоки); `override_hero` — герой наследует модель/статы другого, но GetUnitName() = имя секции.
- **vscripts жизненный цикл**: `Precache()` (до спавна), `Spawn(entityKeyValues)` (при создании юнита, `thisEntity` = юнит), `LinkLuaModifier` для модификаторов, `require` для общих модулей.
- **Панорама**: XML/JS/CSS в content → компиляция → `_c` в game; манифест `custom_ui_manifest.xml`; пути `file://{resources}/...`, `file://{images}/...`; иконки в `panorama/images/custom_game/`.
- **События и данные**: `ListenToGameEvent` (серверные события), `CustomGameEventManager` (клиент-сервер), `CustomNetTables` (синхронизация таблиц), `PlayerResource`, `GameRules`, `GameRules:GetGameModeEntity()`.
- **Частицы**: исходники vpcf в `content/particles/`, манифест `particles/particles_manifest.txt`, прекэч через `PrecacheResource("particle", ...)`; рантайм-управление через `ParticleManager` (CreateParticle/SetParticleControl/DestroyParticle).
- **Модели/звуки**: модели в vpk или `models/`, звуки через `soundevents/` (vsndevts), прекэч моделей через `PrecacheResource("model", ...)`.
- **Инструменты**: `resourcecompiler.exe` (компиляция ресурсов), `vpk` (бинарный каталог `pak01_dir.vpk` — строки можно искать rg -a), консоль игры `-console -condebug`, `console.log`.
- **Dota 7.37+**: герои используют `AbilityInnate` (врождённые способности) и обновлённые слоты Ability1-6 — при добавлении кастомных героев учитывать.

## 2026-08-08: Тиры аугментов масштабируют прибавку карт-статов (common ×1, rare ×2, epic ×4)

- **Проблема**: карты-статы способностей при выдаче накапливали ОДИН ролл ±25% (`add_sum += rolled`) независимо от тира орба — epic-пик давал столько же, сколько common (в отличие от AAF, где `count += rarity` 1/2/4). Бонусы-генерики уже масштабировались (`picks += tier`) — их не трогали.
- **Фикс (3 правки, сервер, клиент не затронут)**: `augments_apply.lua:Accumulate` — параметр `tier`, ADD: `add_sum += rolled * tier`, MULT: `mult_product *= (1 - uv) ^ tier` (tier членов асимптоты); вызов из `GrantAbility` передаёт tier. `augments_math.lua:PickDelta` — параметр `tier`, ADD: `return rolled * tier`, MULT: `product_new = product_old * (1 - uv) ^ tier` (WYSIWYG-дельта в пикере = реальная прибавка). `augments_roll.lua:RollAbilityCards` передаёт `tier` в PickDelta.
- **Почему клиент не менялся**: `ComputeBonus` в utils.js и книга/тултипы читают `add_sum`/`mult_product`/`delta` из серверного состояния (`augment_store`) — новые числа подхватываются автоматически.
- **Эффект**: одна и та же карта-стат: common-выдача = base×1 (ролл ±25%), rare = ×2, epic = ×4. Кап исчерпывается тиром быстрее (`current + tier > cap` — работало и раньше). Сверка с AAF: полное соответствие `count += rarity`.
- **Проверено**: grep по вызовам Accumulate/PickDelta (по одному, оба обновлены); тестовая выдача common/rare/epic одной карты (соотношение ~1:2:4) — требует запуска в Dota.

## 2026-08-11: Обход капа маны 65536 (ManaPool, система «резерва»)

- **Проблема**: движок Dota 2 клампит макс. ману на ~65535/65536 (uint16-поле; HP таким капом НЕ ограничен). При 4441 инта (53k маны от инта) + медицинские трактаты (+300 маны/шт, безлимит) пул «застревал» на 65536. Источники капа: тома инта (`books.lua` ModifyIntellect, безлимит), `modifier_medical_tractate` (EXTRA_MANA_BONUS 300×счётчик), `aug_all_attributes` (без cap).
- **AAF кап НЕ обходит** (проверено агентом по референсу): избегает его — мана растёт только от инта/мелких бонусов, доступность кастов через MANACOST_PERCENTAGE_STACKING, у Satan конверсия манакоста в HP, у Charon %-манакосты. Виртуальной маны/кастомного HUD в AAF нет.
- **Решение — `scripts/vscripts/lib/mana_pool.lua` (новый, «резерв»)**:
  - `overcap_max = несрезанный пул − MANA_CAP`; несрезанный = `GetIntellect(true)×12 + medical_tractates×300 + Σ(флэт-мана предметов из KV `bonus_mana`/`mana_bonus` через AbilityKV) + base_estimate` (остаток базы захватывается, пока `GetMaxMana() < MANA_CAP`).
  - Движковая мана ведёт себя ПОЛНОСТЬЮ естественно (касты тратят, реген наполняет, ванильный бар живой). ⚠️ Первый дизайн с «пином» (держать движковую ману полной тикером) ОТБРОШЕН: бар/цифра замирали на 65536 и «не реагировали на трату».
  - В резерв зачисляется ТОЛЬКО перелив: `overflow = max(0, GetMana() + delta − MANA_CAP)` — движок сам зачисляет `min(delta, CAP − текущая)`, сумма ровно delta → двойного начисления нет ни при каком уровне маны (проверено: overcap_cur=0 при покупках на низкой мане).
  - Трата: `BlockCastOrder` в ExecuteOrderFilter — блок при `движковая + резерв < стоимость`; если движковой не хватает, но резерв покрывает → `SetMana`-дополнение из резерва → движок спишет полную стоимость.
  - Реген резерва (тикер 1с): когда движковая полна, её реген уходит впустую → переливаем `GetManaRegen()×1с` в резерв (до overcap_max).
  - Nettable `mana_pool` (добавлена в custom_net_tables.txt): `{cur = GetMana()+резерв, max = GetMaxMana()+overcap_max, oc = overcap_max}`.
  - Хуки: `books.lua:ApplyByName` и `augments_apply.lua` (GrantAbility/GrantGeneric) → `ManaPool:Recalc`; `on_npc_spawned.lua` → `TrackHero`; SyncTick 0.5с/1с (nettable + пересчёт предметов/базы).
  - Ограничения v1 (осознанно): мана-бёрн не трогает резерв; каналы с тиковой стоимостью не добирают из резерва; резерв не регенерит, пока движковая не полна.

  - Поиск ванильной цифры маны: подъём по родителям `CustomUIContainer_Hud → CustomUIRoot → Hud` + `FindChildTraverse("ManaLabel")` + рекурсивный сбор всех экземпляров (глубина 40!) с выбором видимого. ⚠️ Рекурсия глубиной 10 НЕ находит ManaLabel (дерево HUD глубже).

  - Стиль: явный `font-family: "MonoNumbersFont"` (у ванильной панели className пустой — стили через CSS-правило `#ManaLabel`, скопировать класс нельзя), копия fontSize/textShadow, цвет `#ffffff`, `letter-spacing` 2px, текст `cur + " / " + max` (пробелы вокруг `/` = двойной зазор).
