## 0. TL;DR — 5 слоёв «живости»

1. **AI-ритм**: у 90% боссов НЕТ ручного мозга — общий пул `modifier_boss_ai`: тик 1с, взвешенный рандом по скиллам (вес 1000, после пика ×0.618 = «золотое затухание»), пауза после каста `КД + 1..2с + 5..15% КД` — предсказуем «на глаз», но не зациклен. Фазовый скилл (HP≤60%) пробуется **каждый тик до пула**. Ручные ротации — только Brewmaster (приоритет-хил) и Lina Soul (коридоры дистанций, heat) — и ⚠️ у Lina в KV подключён обычный пул, ручной AI «бумажный».
2. **Каст-дирижирование**: каждый скилл = конфиг (`castPoint/castDuration/OnPhaseStart/OnStart/...`). Прекаст = кастбар 100→0 + DEBUFF_IMMUNE/ROOT/−80% вх. урона (боссы) + звук-кью за 0.08с до удара; «окно破招» в хвосте прекаста (DR→0, удар = стан 0.5-1с + КД); срыв ВНЕ окна = само-стан 4с + КД. После удара ~80% скиллов держат канал-лок (`castDuration`) — босс «занят» (постура-лок, AI молчит).
3. **Телеграфы**: линейные/кольцевые, растущие, с ре-аймом (getDirection до «замка» направления), конусные; «честный» ограниченный трекинг (круг догоняет со скоростью ≤limit, потом залипает — от него можно убежать); цвет зелёный→красный (CP15); мигание после 75% времени.
4. **Физика-мувсеты**: тактическая пере-позиция ДО каста (OnPrePhaseMove: отход/подход спиро-поиском с GridNav), тараны с **наказанием за стену** (стан 0.3 + откат — «глупый и виноватый»), захваты-вис + швырки дугой, довороты LockTargetForSpeed (медленный = читаемый), дуги Bezier с синхронизацией анимации к удару, инерция после удара, расталкивание толпы (collision_effect), ScreenShake-акценты.
5. **Перцепция/масштаб**: цель = всегда БЛИЖАЙШИЙ враг (радиус по типу 1500-4500); урон = `damage_rate` × атака моба (и % макс. HP у автоатаки через KV-поле); постура 1/N от игроков рядом (2500); энрейдж <10% (+10/−10%); фаза = «шоу-окно» 6с инвулн со скрытием HP-бара + бафф фазы 2.

**Ключевой вывод**: у них «живость» зашита НЕ в AI-мозг, а в сами скиллы (пре-мув-манёвры, цепочки, ре-аймы, каст-бары, телеграфы). AI-пул намеренно тупой и ритмичный — характер создают длительности/движения скиллов.

## 1. AI-слой (кто и как решает «кастовать сейчас»)

### 1.1 Боссы: общий пул `modifier_boss_ai` — `modifiers/modifier_boss_ai.lua` (333 стр.) + способность `boss_ai` (`abilities/monster/boss/_boss_ai.lua`)

| Параметр | Значение | Ссылка |
|---|---|---|
| тик | **1 с** | :30 |
| первый каст | count = rand(2..6) | :29 |
| цель | ближайший враг в **3000** (`GetMinDistanceUnit`) | :304-307 |
| пул | все активные (не-пассивные) скиллы; вес **1000** каждый; исключены `projectile_system_ability`, `twin_gate_portal_warp`; фазовые скиллы — отдельным списком | :32-73 |
| попыток выбрать кастуемый | **≤5** (после каждого — вес ×0.618) | :86-100, :203-212 |
| анти-повтор | вес пикнутого `max(1, floor(weight×0.618))` | :203-212 |
| CanCastSkill | хэндл жив + КД готов + дистанция ≤ castRange (если ≤0 → фолбэк **1500**) + cfg.canCast (nil/UF_SUCCESS) | :237-271 |
| пауза после каста | `count = cd + rand(1..2) + cd·rand(0.05..0.15)` (не «мёртвая» формула, реальная: `cd + rand(−1..3)`, :326) | :102-111, :326 |
| пауза после фазового скилла | `cd + rand(−1..3)` | :308-311 |
| нет цели | count = rand(1..4); каст не удался — rand(1..5) | :317-324 |
| гейты тика | `IsStunned` / `IsMonsterCasting()` / дебаг-тумблер `_G.__debug_monster_ai_enabled__` | :284-327 |
| каст | прямые методы `CastAbilityOnPosition/OnTarget/NoTarget` (НЕ ExecuteOrderFromTable — та же грабля, что у нас) | :186-202 |

Фазовые скиллы (`IsBossPhaseTransitionAbility`) AI достаёт ОТДЕЛЬНО каждым тиком, до пула: `TryCastPhaseTransitionSkill` (:113-128) — условие `CanTriggerBossPhaseTransition` (HP≤60%, не сработан, КД готов, canCast).

**Итог по ритму**: цикл «пауза cd+1..2+5..15%cd (обычно 5-11с при cd 5-8с) + занятость cp+dur (1-6с)» = **~4-7 действий/мин**. Частые скиллы (cd 1-3с, напр. QoP cd=3) — до 10-12/мин. Урон падает на занятость: пока кастует — AI стоит.

### 1.2 Brewmaster — единственный «пул + приоритет» (`boss_brewmaster_ai.lua`, 331 стр.)
Клон пула + `boss_brewmaster_1` («питьё»: хил 30% макс. HP + бафф, стаки +30% HP/+450 dmg) **исключён из пула** (:62-64) и кастуется в первую очередь каждого тика, если готов (:294-298), затем пауза rand(3..5). Пауза после рядовых кастов — как пул (:308).

### 1.3 Lina Soul — ручная ротация (эталон «босса с паттерном», НЕ подключена в KV!)

Вывод: даже эталонный «паттерн-босс» у них на пуле — паттерн создаётся скиллами (heat-системой, фазами), не AI.

### 1.4 Элиты: кастер-пулемёт `modifier_elite_ai` (`modifiers/modifier_elite_ai.lua`, 125 стр.)

### 1.6 Автоатака: `modifier_monster_attack_target_sync` (`modifiers/monster/modifier_monster_attack_target_sync.lua`, 111 стр.)
«Нативное авто-агро → явный приказ атаки»: тик 0.25с; пропуск при стан/канал/IsMonsterCasting; цель = `GetAttackTarget() or GetAggroTarget()` (агро = threat из зашифрованного damagemanager), валидация жива/враг/не-сам; смена цели → `DOTA_UNIT_ORDER_ATTACK_TARGET` (иначе мобы «залипают» на мёртвых); фолбэк — ближайший враг в 3500. ⚠️ В открытом коде НИКТО его не вешает — навешивает зашифрованный `unitmanager` при спавне.

В открытом Lua их никто не читает (потребитель — зашифрованный спавнер; движковое агро делает `AttackAcquisitionRange`). Реальные радиусы целей захардкожены в AI/скиллах.

### 2.2 Различия по юнит-типу (`resolveMonsterCastUnitType`, :26-56)
- **normal**: окно прерывания = ВЕСЬ castPoint (прерываемы всегда); НЕ получают debuff-immune/DR; при срыве нет само-стана 4с и «битой» частицы, только КД. «Обычные мобы — как в ваниле».
- **boss/elite/miniboss**: одинаковы по механике, различаются только дефолтом DR (80/0/0).

### 2.3 Поток каста (машина)
1. `OnAbilityPhaseStart` → токен прекаста (`DoUniqueString`) — ВСЕ отложенные колбэки сверяют токен (защита от гонки/двойного OnSpellStart; для OnPrePhaseMove-скиллов нативный SpellStart «съедается» флагом `_dynamicPrePhaseNativeToken`).
2. `StartPhaseStartLayer`: окно `MyGameMonsterCounterBreak:GetInterruptWindowDuration(caster, ut, castPoint, cfg.counterBreakWindowDuration)` → `modifier_monster_cast_pre_progress` (кастбар) + `ScheduleFinishCue(castPoint−0.08)` + (не-normal) `modifier_monster_cast_debuff_immune{duration=castPoint, DR}` → `cfg.OnPhaseStart` (телеграфы/заряд/лок цели).
3. `OnSpellStart` → мёртв/в стане? `finishNow(interrupted=true)` (OnInterrupt+OnFinish+КД, без штрафов); иначе `cfg.OnStart()` = момент удара; если `castDuration>0` → `modifier_monster_cast_controller` (канал-лок) + `SetPostureLocked(true)`.
4. Контроллер истёк → `cfg.OnFinish` + КД.

### 2.4 Кастбар `modifier_monster_cast_pre_progress` (cast_modifiers :198-345)
StackCount 100→0 каждый кадр (остаток %), ScreenShake (ампл 2, freq 10, dur=castPoint, r=2000), частица `hero_ability_bkb` CP60=castColor. Клиентские сегменты бара — трюк через `GetModifierIncomingPhysical/SpellDamageConstant` + `event.report_max`: физический сегмент = окно прерывания (красный), магический = защита (синий); ширина окна `interruptWindowPct` передаётся трансмиттером.

### 2.5 Защита прекаста `modifier_monster_cast_debuff_immune` (:115-191)
DEBUFF_IMMUNE+COMMAND_RESTRICTED+ROOTED+DISARMED+CANNOT_BE_MOTION_CONTROLLED+отключён поворот. DR-атрибут: вне окна = заданный %, **в окне = 0**. Вход в окно: тик FrameTime, `GetRemainingTime() <= point` → `EnterCounterBreakWindow()` + RefreshAttributes + стоп тика. OnDestroy: `ClearWindow` + снятие `modifier_monster_cast_stun`.

### 2.6 Канал-лок `modifier_monster_cast_controller` (:29-113)
DISABLE_TURNING + COMMAND_RESTRICTED/DISARMED/NO_UNIT_COLLISION (если `__lock_actions`) + CANNOT_BE_MOTION_CONTROLLED. OnDestroy: `SetPostureLocked(false)` + `cfg.OnFinish`. `isNotMove=false` разрешает повороты во время канала (10 файлов).

### 2.7 Прерывание/контр-брейк
- **Срыв А (вне окна)**: OnAbilityPhaseInterrupted → InterruptPrecastFlow: OnInterrupt+OnFinish, «битая» частица, само-стан 4с, КД, Stop.
- **Срыв Б (thunderized counter-break, только `cfg.thunderizedCounterBreak=true` — 4 файла: elite_103/114/115, storm_spirit_4)**: удар по кастующему в окне → `_skipNextPhaseInterrupted` (0.2с гард), стан 0.5-1с, КД, `TriggerThunderizedCounterBreak` → событие ON_POSTURE_COUNTER_HIT → постура +15.

### 2.8 Статистика по 383 конфигам abilities/monster/** (461 файл, 0 зашифровано)
**castPoint** (дефолт 0.5): 0 — 76 (19.8%), 0.01-0.3 — 32, 0.31-0.5 — 67, **0.51-1.0 — 134 (35%)**, 1.01-1.5 — 47, 1.51-2.0 — 16, 2.01-3.0 — 7. Среднее ~0.63с, медиана 0.5-0.75с.

## 3. Телеграфы (язык боя)

Ядро: `modifiers/monster/monster_warning_effects.lua` (407 стр.); обёртки в monster_base.lua:662-692; статистика по китам: WarningEffect 147 вызовов/108 файлов, WarningRing 100/91.

### 3.2 Кольцевой `WarningRingEffect(caster, center, radius, duration, options)`

### 3.3 «Честный» ограниченный трекинг `EliteCreateLimitedWarningTargetTracker` (elite_showcase_utils.lua:53-137)
Кольцо догоняет цель со скоростью **не выше followSpeed** (напр. 330-380); после `followDuration` (0.5-1с) центр **залипает навсегда** — игрок успевает выйти. `lock()` = финальная точка удара/блинка (elite_103 блинк в залоченную точку, elite_210 падение снаряда, elite_309 казнь). Пере-резолв при смерти цели через `resolveTarget`.

### 3.4 Прочее
- Конусы (ширина start→end), «растущие» полосы (CP1 уезжает каждый кадр, phantome_ab1: ×17/фрейм), красные думми-полосы (boss_beast: рост 40/тик 0.03 до 2500).

## 4. Движения и физика (мувсеты «живости»)

### 4.1 Тактическая пере-позиция ДО каста (OnPrePhaseMove) — «босс не кастует с места»
Фреймворк: monster_base.lua:318-354 — вешает `modifier_monster_cast_pre_move`, мониторит стан каждый кадр (`StartManualPrecastInterruptMonitor`), таймаут `cfg.prePhaseMoveTimeout` (нигде не задан), колбэк `finishMove()` → StartPhaseStartLayer + ручной отсчёт castPoint → удар. **Время до удара = длительность пре-мува + castPoint.**

**Эталон-отход (phantome_ab1.lua:57-201)**: цель = ближайший в 3500; бюджет: цель не дальше **1200**, отойти на **500**; кандидаты — **4 дистанции {500,400,300,200} × 11 углов {0,±20,±40,±60,±80,±90}** от направления «от цели»; валидация `IsValidAwayMovePoint`: отход >64, дистанция до цели ВЫРОСЛА (>+1), не дальше 1200, `GridNav:IsTraversable` + не IsBlocked + `CanFindPath`; скорость = max(GetIdealSpeed(), **900**); жест бега `ACT_DOTA_RUN` ×1.35; `Mover(point, dur, arrival-cb(≤64→done+stop), false, true)` + **страховочный таймер `dur+FrameTime`** (:107-110); точка не найдена/уже близко → `done()` — каст с места (мягкая деградация).

Варианты: отход на **800** с потолком 2100 (boss_lina_soul_2:109-226, мин.скорость 700); возврат к спавну/центру комнаты (boss_lina_soul_1:113-191, phantome_ab6:63-130 — мин. 900); **подход К цели** — точка в 200 перед целью, валидация «стало ближе» (phantome_ab2_1:120-146), длительность кламп ≤1с; пере-позиция вокруг цели на 500 от ЦЕЛИ с выбором угла по удалённости от центра арены (phantome_ab1_1/ab1_2:120-225, коридор 500-800 от кастера).

### 4.8 Микро-паттерны (повторяющиеся решения)
- **hit-map**: каждый рывок/волна/лазер — Set по entindex против двойного попадания; лазеры — hit-Cd 0.4с/цель.
- **dash-стоп**: первый контакт = стоп рывка (damageOverTime флаг «остаток без урона»).
- **ре-аим**: между фазами каста босс заново ищет цель (`GetMinDistanceUnit` на каждом шаге цепочки).
- **анти-кайт**: прыжки/рывки с дистанцией от цели (AiDistance(target, min, max, ±offset)).
- **подкидывание-«нок-ап»**: высота отдельным параметром (monkey_ab1 ApplyKnockup, elite_033 STOMP_KNOCKUP 0.5с/450).
- KnockBack: `origin_pos` = разлёт от точки; без него — от кастера; `stun=true, stunDuration` — стан в отбросе.
- Каждая точка-«куда-то» — GridNav-валидация (IsTraversable/IsBlocked/CanFindPath/FindPathLength≠−1), часто шагающий поиск (шаг 48) и 8-24 ретраев.

## 5. Перцепция, масштаб, постура, фазы, саммоны

### 5.1 Таргетинг
Только ближайший враг: normal 1500-2000, elite 1800-3500 (тип 3500), boss 2000-4500 (тип 2500-3500; максимумы: monkey_ab4/ab7 4500). Никакого threat-таргета в открытых скиллах нет (GetAggroTarget — из шифрованного damagemanager, используется attack_target_sync).

### 5.2 1/N-масштабирование (`utils/boss_encounter_scaling.lua`, открыт)
`GetNearbyEnemyPlayerShareMultiplier = 1 / max(1, уникальных игроков-врагов в 2500)`. Применяется ТОЛЬКО к постуре (r 2500 совпадает с «камерой выхода босса»). HP/урон от числа игроков НЕ масштабируются (в отличие от нашего замысла).

### 5.3 Постура (числа, все открыты)
`modifiers/state/posturebarrules.lua` + `modifier_cs_posture_bar.lua`:
- порог 100; +1 стак за 1% макс.HP урона × 1/N; **decay отключён** (0/сек);
- «стан копит постуру»: пока на юните нативный стан — **+2 каждые 0.03с** (баш-цепочки приближают стан-лок);
- контр-хит: +floor(threshold×0.15) = +15;
- завершённый каст: −floor(threshold×0.03) = −3;
- **стаггер при 100**: `modifier_generic_stunned` 8с + SlowDownServerRate(0.3, 0.2) + стекло-звук/частица; урон во время стаггера сокращает его: **−1с за каждые 5% HP**;
- `IsPostureLocked` (канал-контроллер) — иммун к набору;
- тик FrameTime по HP-дельте (без событий урона! — грабля params.unit у нас 2026-09-03, у них тот же обход: дельта HP, `_lastHp − GetHealth()`), множитель 1/N рефрешится раз в 1с; значение в StackCount (движковый синк).

### 5.4 Фазы (`boss/boss_phase_transition_ability.lua`, открыт)
- порог **HP ≤ 60%** (переопределяемо; у axe_soul_5/tiny — 50%), одноразово;
- возврат к спавну Mover'ом **0.8с** (шаблон-саммон — 0.6с);
- окно: `modifier_boss_phase_transition_window` 6с: INVULNERABLE+STUNNED+ROOTED+DISARMED+COMMAND_RESTRICTED+NO_HEALTH_BAR, жест-луп каждые 1с, **босс-бар скрывается** (MyGameBossBarManager);
- по концу — `modifier_boss_phase_two_buff`: **+10% исх., −10% вх. урона, +20% MS, +20 AS**;
- state: TRANSITIONING → AFTER (наследники читают и меняют поведение; лайк-кап: наш `unit.travaler_phase`).

### 5.5 Энрейдж `modifier_cs_boss_low_health_enrage`
HP<10% → +10% атак +10% DR (тик 0.1с, RefreshAttributes).

### 5.6 Саммоны — единая фабрика
`MyGameUnit:CreateSummonedUnitAsync({unitName, summonTag, maxSummons, position, roomId, team, owner, summoner, destroyWithSummoner, findClearSpace, onSpawn})` (зашифрована): пул по тегу с лимитом (повторный саммон того же тега не превышает maxSummons), destroyWithSummoner. **Защита спавна** — `modifier_monster_born` (ROOTED+STUNNED+NO_HEALTH_BAR 1-1.2с + жест + модель-рост). onSpawn-колбэки: разворот к боссу, спец-пре-атаки (гончие beast: prepare 0.7с инвулн → рывок 1300/0.55с). Фазовые саммоны по шаблону `boss_simple_phase_summon`: 5 юнитов по кругу R=620 на 0.65с окна, эффект-петля 1.5с.

### 5.7 Leash/return
`modifier_monster_leashing` (из шифрованного кода): тик 0.5с MoveToPosition домой + **полный хил**, инвулн+OUT_OF_GAME, MS 800. Wander-мобы «лишатся» к герою (1300), а не к спавну.

## 12. Сверка с прошлым досье и «забрать себе» (shortlist)

Уже перенесено у нас (lib/duel_bosses, 2026-08-31/09-02): теллуры (те же частицы!), Mover/Bezier/KnockBack, окно контр-брейка, постура-бар (полная схема + стаггер-сокращение уроном), каст-локи, фаза-окна, collision-подобные механики.
**Кандидаты «следующего эшелона»** (по убыванию ценности):
1. Пре-позиция перед кастом (OnPrePhaseMove: спиро-поиск 4×11, GridNav, min-speed 900, таймер-дубль, мягкий done) — даёт «босс не кастует с места»;
2. Кастбар с сегментами «окно/защита» (стек 100→0 + report_max трюк — без отдельного неттэйбла);
3. Честный limited-tracking телеграф (followSpeed + followDuration + lock);
4. ×0.618 взвешенный пул с ≤5 пере-роллами и паузой `cd+1..2+5..15%cd` (нашему AIController — как опция ротации «как у китайцев», выключаемая);
5. Само-стан 4с за срыв вне окна (у нас есть), но добавить «нормальный» уровень: обычные мобы прерываемы без штрафа (уже так);
6. Финиш-кью звук за 0.08с до удара + ScreenShake-таблица (каст 5-8/удар 10-20);
7. Энрейдж <10% (+10/−10% тик 0.1с) — тривиально;
8. Фазовый «шаблон-саммон»: возврат → окно 6с инвулн/NO_HEALTH_BAR/скрытие бара → бафф (+10% исх., −10% вх., +20% MS, +20 AS) — у нас travaler-фазы без шоу-окна и bar-hide;
9. KV-поле автоатаки «% макс. HP» (Custom_OnAttackHealthPctDamage) — превращает любой моб в угрозу без Lua;
10. Пассивные «эпизоды» (boss_009: HP≤55% → саммон каждые 15с; Lina fireball-марка каждые 6с, блокирующая AI) — «фоновая жизнь» между кастами.
